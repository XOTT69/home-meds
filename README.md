# home meds

Приватна PWA для домашньої аптечки: облік ліків, контроль строків придатності, списки покупок і чеклісти для подорожей.

## Можливості

- аптечка з категоріями, локаціями, зручним обліком у пачках, таблетках, капсулах, мілілітрах або штуках, мінімальним запасом, строком, активною речовиною, дозуванням, застереженнями та приватним фото упаковки;
- автоматичний список покупок, коли залишок доходить до заданого мінімуму, і ручне додавання будь-чого, чого немає вдома;
- автозаповнення картки за введеною назвою, сканування штрихкоду з пошуком у відкритому довіднику FDA, а також локальне OCR-розпізнавання тексту з фото упаковки;
- пошук, швидкі фільтри, друкований експорт аптечки у PDF та безпечні нотатки про застосування;
- сімейні профілі з редагуванням, алергіями та примітками; у картці ліків можна позначити, кому вони підходять;
- спільна аптечка для родини: кожен заходить зі свого акаунта, а власник призначає роль редактора або лише перегляду;
- журнал спільних змін для ліків, подорожей, чеклістів і профілів родини;
- повне редагування та видалення ліків, подорожей і пунктів чекліста;
- додавання ліків з аптечки до чекліста конкретної подорожі та шаблони «вікенд», «море», «авто / дорога», «з дитиною»;
- авторизація за email і паролем та безпечне відновлення пароля;
- синхронізація даних між пристроями через Supabase та строгі правила доступу до рядків (RLS);
- інсталяція як PWA, офлайн-відкриття після першого запуску і браузерні нагадування про строки придатності.

Нагадування перевіряються, коли Home Meds відкрито. Вони не маскуються під серверні push-нагадування: для сповіщень на повністю закритому пристрої потрібен окремий серверний сервіс.

> Застосунок організовує інформацію й не дає медичних призначень. Завжди перевіряйте інструкцію до препарату та консультуйтеся з лікарем або фармацевтом.

Автоматичний пошук залежить від країни й наявності препарату у відкритому довіднику. Дані зі штрихкоду підставляються як довідка для перевірки; розпізнаний з фото текст дає лише ймовірного кандидата, без автоматичного призначення дозування.

## Локальний запуск

```bash
npm install
npm run dev
```

Для перевірки production-збірки:

```bash
npm run build
```

## Підключення безкоштовного Supabase

1. Створіть безкоштовний проєкт у [Supabase](https://supabase.com/).
2. У **SQL Editor** виконайте по черзі [schema.sql](./supabase/schema.sql), [міграцію профілю й подорожей](./supabase/migrations/20260914_personalize_home_meds.sql), [міграцію родини й приватних фото](./supabase/migrations/20260914_family_inventory.sql), [міграцію спільної аптечки](./supabase/migrations/20260914_shared_households.sql), [професійну міграцію ролей і журналу](./supabase/migrations/20260914_cabinet_pro.sql) та [міграцію ручних покупок](./supabase/migrations/20260914_manual_shopping.sql).
3. У **Authentication → URL Configuration** додайте URL сайту та `https://xott69.github.io/home-meds/` до Redirect URLs.
4. Створіть `.env.local` за прикладом `.env.example` і вставте **Project URL** та **Publishable key** з Supabase. Не використовуйте `service_role` key.

## Безкоштовний деплой на GitHub Pages

Workflow вже готовий у `.github/workflows/deploy-pages.yml`.

1. У репозиторії відкрийте **Settings → Pages** і виберіть джерело **GitHub Actions**.
2. Після push у `main` сайт буде опублікований на `https://xott69.github.io/home-meds/`.

`VITE_SUPABASE_URL` і publishable key вже записані у `.env.production`: це публічні параметри браузерного застосунку. Не додавайте туди `service_role` або `sb_secret` key.

Безкоштовний SMTP Supabase призначений для розробки та має малий ліміт на листи. Для публічного запуску потрібно підключити власний SMTP-провайдер; для приватного тестування стандартного достатньо.

## Спільна аптечка для родини

1. Власник виконує міграцію спільного доступу вище, входить у застосунок і відкриває **Профіль → Спільна аптечка**.
2. Натискає **«Створити код запрошення»** та передає код лише людині, якій довіряє.
3. Кожен учасник створює й підтверджує власний акаунт, а потім у тому ж розділі вводить код.

Власник може призначити кожному учаснику роль **редактора** або **лише перегляд**. Редактори можуть змінювати спільні дані, а роль перегляду гарантується правилами бази даних, а не лише інтерфейсом. Власник може прибрати учасника; після цього код запрошення одразу змінюється, тож старий код не дозволить повернутися. Ім’я акаунта залишається особистим. Старі приватні записи людини, яка приєднується, нікуди автоматично не копіюються.
